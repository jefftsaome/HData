# 事故知识库(INCIDENTS)

> 本文件记录踩坑获得的存活逻辑。每条 = 现象 / 根因 / 补丁位置 / 失效条件。
> **删补丁前先查这里**——这些逻辑都是事故换来的，删错=踩回坑。
> 配套阅读：`docs/GLOSSARY.md`(术语)、`docs/ARCHITECTURE.md`(结构)。

## 1. 2026-07-27 静默事件：密集建连被 WAF 静默

- **现象**：30 账号经 3 出口集中建连后整批会话被静默(连接活着但无数据)
- **根因**：同 IP 密集 WS 建连触发平台 WAF 403/短封
- **补丁**：`client/_shared.py` 分片建连**按代理出口分组限速**——同出口串行、间隔 18s；不同出口并行；无代理全部视为同组
- **失效条件**：平台 WAF 规则变化

## 2. 2026-08-01 两次全体断连

- **现象**：全体连接以 1011 断开(两次)
- **根因**：传输层库默认 20s WS ping/pong 在事件循环被进桌风暴打满时 pong 排队超时；且 ping 帧是官方客户端不发的多余指纹
- **补丁**：`client/transport.py` 关闭传输层 ping，改用业务层心跳(协议 pid=3, 10s) + 收帧静默看门狗(120s)
- **失效条件**：库行为或平台对心跳的容忍度变化

## 3. 2026-08-02 02:25 空闲分片误杀

- **现象**：空闲分片(0 桌)每 120s 被收帧静默看门狗误杀重建一轮
- **根因**：空闲分片收不到任何帧是正常态(心跳是客户端单向发送、服务端不回)；按"有帧即活"判死会把空闲片全误杀
- **补丁**：`client/transport.py` `expect_traffic` 标志——空闲分片豁免看门狗(TCP 半死会从心跳发送侧暴露)
- **失效条件**：心跳发送不再可靠时

## 4. 2026-08-02 断供事故：服务器切订阅但连接活着

- **现象**：多台订阅被服务器静默停推数据帧，无控制帧、心跳照走，任何"有帧即活"看门狗失效
- **根因**：服务器对多台订阅会话有固定 ~8 分钟 TTL，到期静默停推；官方客户端表现为"多台模式自动退出"
- **补丁**：`client/tables.py` MultiplaySession 按数据帧判活(`_DATA_PIDS = {103,104,106,107,160,161}`)，心跳/控制帧不计；`resubscribe()` 在 TTL 到期前主动重发 301 订阅
- **失效条件**：服务器 TTL 机制变化

## 5. 2026-08-02 schema 解码逐字节错位

- **现象**：10089 大厅 231 桌解出 246 个假元素，一半丢 tableId/gameTypeId，body/bits 各剩一半
- **根因**：服务器给 HallGameTable 插入新字段(allGameTopSort)后，旧内置 schema 逐元素错位
- **补丁**：schema 热更新机制——用官方解码器仲裁 + 新版 schema 实测(body 0 剩余、231 桌与 hallDetails/totalTable 完全吻合破案)；`schemacodec.py` 登录响应 `protocolCodecConfig` 或 10115 推送热更新
- **失效条件**：协议 schema 再次变化

## 6. 2026-07-17 签名体系：wasm 动态签名必须优先

- **现象**：静态签名表失效导致 API 请求被拒
- **根因**：服务器对 /game/api 等强制校验每请求唯一签名
- **补丁**：`auth/api_sign.py` wasm 动态签名(每请求唯一)；`auth/headers.py` 三层回退链：wasm → 手动捕获签名表 → uuidToBase64 解密表
- **失效条件**：wasm 签名算法被服务端更新

## 7. 客户现场(2026-08-04)HTTP 登录域名失效自愈

- **现象**：客户 f87tmo 404 实锤——API 返回非 JSON 响应
- **根因**：域名缓存失效(域名小时级轮换)但缓存未清
- **补丁**：`auth/http_login.py` `ApiDeadError` 穿透——API 非 JSON 响应自动失效域名缓存重解析切换；非 JSON 响应日志带 http 状态+响应体预览
- **失效条件**：域名轮换机制变化

## 8. 浏览器登录现场 Workarounds(2026-08-04)

- **现象**：headless shell 能起进程但 new_page 报错；完整 Chromium 可绕过；首次崩溃留下的损坏 profile 导致必失败
- **补丁**：`auth/browser_login.py` 四级容错——清损坏 profile 重试 → channel=chromium → 条件 headful → 可见浏览器人工登录
- **细节**：顺序必须先 new_page 再关旧页(先关后开必现)；request 事件可能错过，兜底直接轮询所有页面
- **失效条件**：Playwright/Chromium 版本行为变化

## 9. 平台账号信任等级(非代码事故，运营认知)

- **现象**：29 个批量新号从出生起零数据帧(控制帧照通)；linbing1 单号曾收 174 桌
- **根因**：平台按账号信任等级发放数据，额度会持续收紧(174→26→9，掐掉不恢复)
- **应对**：账号池 status 0/1/2 管理、换号轮换维持观察号(每局 5 局不下注被踢 ~2.5 分钟)
- **相关**：设备 UUID 目前所有号共用 9f790aa1…(待修，见 PROJECT.md 待办)
